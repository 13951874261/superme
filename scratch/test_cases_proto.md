# 测试用例：人机对战沙盘 - 自定义对手选择

## 测试用例 1：对手选择列表显示自定义原型

- **菜单路径**：博弈模块 → TAB 3: 博弈论实操推演（人机对战） → 博弈对手选择
- **测试数据**：
  - 用户已创建 2 个 personal_prototypes：
    - 名称："James VP"，类型："恐惧驱动型"，描述："极其注重个人利益安全"
    - 名称："张总监"，类型："多疑多虑型"，描述："对细节事事过问"
- **预期结果**：
  1. 固定对手列表下方显示分隔线 + "已有人性档案" 标题
  2. 两个原型各显示为一个按钮，格式：`James VP (恐惧驱动型)`、`张总监 (多疑多虑型)`
  3. 固定对手（VP/副总/总监）和"自定义博弈对手..."按钮保持不变
- **对应需求**：加载当前用户已创建的 personal_prototypes

## 测试用例 2：点击自定义原型自动装配参数

- **菜单路径**：同上
- **测试数据**：点击 "James VP (恐惧驱动型)" 按钮
- **预期结果**：
  1. 该按钮高亮（黑底白字），其他按钮恢复默认样式
  2. 左侧面板展开自定义表单区域，显示：
     - 对手姓名 / 职位：`James VP`（已填充）
     - 人性弱点分类：`恐惧驱动型`（已填充）
     - 选择博弈模型：`囚徒困境演化版`（默认）
  3. 右侧危机场景描述框初始化为：`【对手性格特征】：极其注重个人利益安全\n【对立博弈场景】：`
  4. "已选对手特征" 面板隐藏（因为不是固定对手）
- **对应需求**：允许用户选择自定义对手参与对局；将所选对手的画像、行为特征和博弈策略传递给现有分析流程

## 测试用例 3：选择固定对手时自定义原型不高亮

- **菜单路径**：同上
- **测试数据**：先点击 "James VP"，再点击 "空降的改革派 VP"
- **预期结果**：
  1. "空降的改革派 VP" 高亮，"James VP" 恢复默认样式
  2. 左侧面板显示 "已选对手特征" 面板（弱点原型、推荐模型）
  3. 自定义表单区域隐藏
- **对应需求**：保留原有固定对手

## 测试用例 4：无自定义原型时不显示档案区域

- **菜单路径**：同上
- **测试数据**：用户未创建任何 personal_prototypes（prototypes 数组为空）
- **预期结果**：
  1. 固定对手列表下方直接显示 "自定义博弈对手..." 按钮
  2. 不显示 "已有人性档案" 标题和空列表
- **对应需求**：没有自定义对手时，继续使用固定对手，不影响原有功能

## 测试用例 5：提交对局时自定义原型参数正确传递

- **菜单路径**：同上 → 点击"启动人机博弈对决推演"
- **测试数据**：
  - 选择 "James VP (恐惧驱动型)"
  - 补充危机场景："【对立博弈场景】：年度预算会议中..."
  - 填写应对策略："我的反制策略是..."
- **预期结果**：
  1. 提交按钮可用（所有必填字段已填）
  2. 后端收到的 `case_text` 包含：
     - `【博弈对手姓名 / Name】: James VP`
     - `【人性分类 / Weakness Type】: 恐惧驱动型`
     - `【博弈局势描述 / Dilemma Detail】: 【对手性格特征】：极其注重个人利益安全\n【对立博弈场景】：年度预算会议中...`
  3. 任务成功提交到任务中心
- **对应需求**：将所选对手的画像、行为特征和博弈策略传递给现有分析流程

## 测试用例 6：自定义对手与固定对手切换后表单重置

- **菜单路径**：同上
- **测试数据**：
  1. 点击 "James VP" → 姓名自动填充为 "James VP"
  2. 点击 "空降的改革派 VP" → 切换到固定对手
  3. 再次点击 "自定义博弈对手..." → 表单应清空
- **预期结果**：
  1. 切换到固定对手后，自定义表单隐藏
  2. 重新点击 "自定义博弈对手..." 后，表单字段为空（姓名、类型重置为默认）
- **对应需求**：保留原有固定对手；自定义功能不影响原有交互
