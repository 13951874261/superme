# Deep Interview：每日定时任务日志进入后台任务中心

## 元数据

- Profile：Standard
- Context：Brownfield
- 轮次：12
- 初始歧义度：62%
- 最终歧义度：8%
- 目标阈值：20%
- Context snapshot：`.omx/context/daily-cron-task-logs-20260808T105600Z.md`

## 已确认事实

1. 现有顶栏“提纯：查看队列”打开 `GlobalTaskCenter`。
2. 现有任务中心使用 `taskQueue`，任务包含状态、进度、日志、结果和错误。
3. 终态任务约 30 分钟后清理，无法满足早晨检查每日 02:00 任务的需要。
4. 每日 Cron 当前不创建队列任务，只有 console、临时 summary 和业务表状态。
5. 一次每日执行包含每日唤醒、每日破绽词汇、64 个长文组合及 DailyListen。
6. 原设计把可视化失败队列列为非目标，本需求明确改变该边界。

## 访谈记录

### Round 1：主要用途

问题：日志的首要用途是什么？

用户决定：每天检查最近 7 天执行结果。

影响：日志必须跨 30 分钟队列 TTL 持久保存，且支持按执行日期查看。

### Round 2：展示粒度

问题：一次每日执行如何展示？

用户决定：一张“每日定时任务”主卡片，内部按唤醒、破绽词、长文、精听分区。

影响：禁止把 64 个长文组合平铺成 64 张任务卡。

### Round 3：详细程度

问题：64 个长文组合记录到什么粒度？

用户决定：默认显示进度汇总；失败组合显示完整错误；成功组合可展开查看。

影响：UI 默认保持紧凑，数据层仍保留成功组合的可查询明细。

### Round 4：首版能力

用户补充：

- 必须提供手动重跑。
- 必须显示每次执行的实际入参。
- 必须显示每个入参的获取方式。

### Round 5：入参安全

用户决定：

- 显示实际入参值。
- API 密钥完全隐藏且不得由 API 返回。
- 用户画像、薄弱点等长文本默认折叠，可主动展开。

### Round 6：重跑范围

用户决定：

- 支持整次重跑。
- 支持仅重跑失败模块。
- 支持仅重跑失败长文组合。

### Round 7：产品命名

用户决定：

- 顶栏入口改为“后台任务：查看队列”。
- 抽屉标题改为“后台任务中心”。

### Round 8：重跑入参语义

用户决定：

- “重跑失败项”复用原执行的入参快照，保证可复现。
- “整次重新执行”重新获取当前入参。
- 每次重跑创建新执行记录，不覆盖原日志。

### Round 9：边界闭环

用户确认首版：

- 不改变现有 02:00 触发策略。
- 不增加无人值守自动重试。
- 不提供日志下载或导出。
- 不返回任何 API 密钥。
- 允许 Agent 在不改变现有任务行为的前提下决定 SQLite 表结构、API 拆分、React 组件拆分及轻量动画细节。

### Round 10：多用户可见性

用户决定：后台任务中心只显示当前登录用户相关的步骤、日志和入参。

影响：API 必须在服务端按当前用户过滤，不得把同一全局 Cron 中其他用户的数据发送给前端。

### Round 11：整次重跑的用户边界

用户决定：当前用户点击“整次重新执行”时，只执行当前用户的唤醒、破绽词、长文和精听，不重新执行其他 Cron 目标用户。

### Round 12：入参来源呈现

用户决定：

- 默认显示用户可读的中文来源说明。
- 可展开查看表名、字段名、函数、筛选条件、排序、截断、拼接和兜底规则。

## 压力测试结论

### 假设一：直接把 Cron 塞进现有 taskQueue 即可

不成立。现有终态记录约 30 分钟后删除，无法支持最近 7 天查看。

### 假设二：日志越详细越好

需限制默认展示。每用户每天最多 64 个长文组合；默认全展开会造成严重信息噪声。最终确定为“汇总优先、失败完整、成功可展开”。

### 假设三：重跑统一使用一种入参语义

不成立。故障复现需要旧快照，而整次重新执行需要当前数据。最终采用混合语义。

### 假设四：显示实际入参没有安全风险

不成立。运行参数包括画像、薄弱点、历史词汇等用户数据。最终要求长文本折叠、密钥永不返回。

## 最终意图

把每日后台生成从只能查看服务器 console 的黑盒，变成可在现有任务中心检查、追溯和人工恢复的可观察任务；同时保持现有定时策略和其他异步任务行为不变。

## 最终补充边界

- 日志可见范围固定为当前登录用户。
- UI 中的“整次重新执行”固定为当前用户级任务，不是全局 Cron。
- 入参来源采用“中文摘要 + 技术详情展开”的双层呈现。
