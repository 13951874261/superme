# 个性化多角色与即兴演讲场景重构规格

## 元数据

- Profile：Standard
- Context：Brownfield
- Rounds：8
- Final ambiguity：4%
- Threshold：20%
- Context snapshot：`.omx/context/personalized-speaking-scenes-20260903T042000Z.md`

## 意图

解决多角色练习主题长期固定、即兴演讲缺少可执行指引的问题；让每日练习内容结合用户画像持续变化，同时保证刷新即时可感知。

## 目标结果

### 多角色练习

- 展示个性化场景背景、角色、冲突、目标、任务和开场内容。
- 提供“换一题”和“重新生成”。
- 场景切换后沿用现有战斗状态重置规则。

### 即兴演讲

- 展示主题、场景背景、用户身份、目标听众、发言目标、关键矛盾。
- 展示推荐结构、可用观点、关键词和开场示例。
- 提供“换一题”和“重新生成”。

## 数据与生成

- 每位用户每天独立缓存最多 10 个场景，两类场景共享该上限。
- 默认建议多角色 5 个、即兴演讲 5 个；实现可依据最近使用比例调整，但每类至少 2 个。
- 每日预生成复用 `dailyPackCron`、`dailyCronRunService`、`taskQueue`。
- 画像复用 `user_memories`、`profileInject.js`、`resolveProfileForDify()`。
- 生成输入至少包含当前主题、学习阶段/CEFR、训练目标、近期薄弱项、职业画像、历史去重信息和场景类型。
- 重新生成时由服务端读取最新画像；不信任前端画像正文。
- 达到 10 个后，重新生成替换当前场景；未满时可新增。
- 生成失败保留当前场景。

## 性能契约

- 用户点击“换一题”后 300ms 内必须收到并展示至少一个非空场景内容片段。
- 加载状态、骨架、心跳、空 SSE 事件不计入有效内容。
- 硬 SLA 通过服务端缓存流式返回实现；不得依赖实时公网模型 TTFT。
- 缓存缺失时保留当前场景并启动生成，不用空内容替换。

## Dify/LLM 契约

- 优先使用现有 Dify 服务端代理与流式 SSE 读取方式。
- Dify 开始节点声明 `user_current_profile` 及其他所需输入变量。
- 使用稳定账号 ID 作为 Dify `user`。
- API Key 仅存在服务端环境变量。
- 输出采用固定 JSON Schema；服务端执行类型、长度、枚举和空值校验。
- 可用兼容 OpenAI Chat Completions 的服务端 LLM 作降级，但不得把 Key 写入前端或仓库。

## 缓存与隐私

- 缓存至少按 `user_id + date + scene_type + scene_id` 隔离。
- 保存生成时的画像 hash，用于审计；当天画像变化不自动废弃既有缓存。
- Cron 日志不得保存画像原文，只保存 `profile_present`、`profile_length`、`profile_hash`。
- 同一用户当天场景应去重。

## 范围

### In Scope

- 多角色练习与即兴演讲界面布局重构。
- 个性化场景数据模型、缓存、API、每日预生成、换题与重新生成。
- Dify/LLM 流式生成与验证。
- 300ms 首个有效内容 SLA 验证。
- 必要的契约、服务和前端测试。

### Out of Scope / Non-goals

- 不重构自由即兴对话。
- 不改变现有导航层级。
- 不新建画像体系、调度框架或任务中心。
- 不因画像变化自动重生成全部当日缓存。
- 不修改现有 Dify 密钥配置语义。
- 不影响其他英语模块及口语功能。

## 决策边界

实现方可自行决定：视觉细节、响应式布局、字段显示顺序、场景字段名称、两类缓存初始分配细节。

必须再次确认：改变导航、修改其他口语功能行为、迁移/删除现有 Dify 应用、扩大每日上限、发送额外敏感画像字段。

## 验收标准

1. 每用户每天缓存总数始终不超过 10。
2. 不同用户无法读取或替换彼此场景。
3. 多角色与即兴演讲均可换题、重新生成。
4. 缓存可用时，点击至首个非空内容展示 P95 ≤300ms；同时记录最大值用于硬 SLA 排查。
5. 满额重新生成只替换当前项，总数不增加。
6. 重新生成请求读取服务端最新画像。
7. 生成失败时原场景仍可继续使用。
8. 重复点击只产生一个有效生成任务。
9. 多角色场景切换正确清理旧会话上下文。
10. 即兴演讲切换正确清理旧录音、转录、提示、评分和范文。
11. 审计日志不包含画像正文或 API Key。
12. 现有角色练习、即兴演讲、自由即兴对话关键回归测试通过。

## 测试场景

- 菜单：英语战略 → 口语练习 → 角色练习；数据：有 10 个缓存场景；操作：换题、满额重新生成；预期：300ms 内显示新内容，重新生成替换当前项。
- 菜单：英语战略 → 即兴演讲；数据：B2 用户、跨文化沟通短板；操作：换题；预期：返回含身份、听众、目标、结构和开场实例的个性化题目。
- API：用户 A 请求用户 B 场景 ID；预期：404/403，不泄露数据。
- API：重新生成期间连续点击；预期：单任务、原场景保留至成功替换。
- API：生成服务超时/空输出/无效 JSON；预期：失败状态，原场景不变。

- 多角色当前术语：scene、roles、conflict、mission。
- 即兴演讲当前术语：topic、prompter、evaluation、exemplar。

## 风险

- 300ms 硬 SLA 只能由缓存保证；实时重新生成仍受公网模型延迟影响。
- 当前 Cron 日志存在画像正文泄漏风险；新链路不得复制该行为。
- 仓库部分 Dify YAML 与服务端 inputs 有版本漂移；实施前须核对目标应用参数。
