# 统一主题设计（方案 B）

日期：2026-08-23  
状态：已按方案 B 开工  
用户拍板：方案 B；侧栏文案改为「当前主题」；换主题后全站实时联动，来源唯一

## 目标

同一个用户、同一个时刻，全站只能有一个中文主题。

用现网 `lzhmy` 在 2026-08-22 的数据举例，改完后必须变成：

| 地方 | 现在 | 改完后 |
| --- | --- | --- |
| 后台主题表 | 新人报到 | 新人报到 |
| 侧栏 | 海外信贷谈判与博弈 | 当前主题：新人报到 |
| 英语练习 / 多角色 / 演讲 | 新人报到 | 新人报到 |
| 今日包接口返回的「当前主题」 | 商务谈判：让步与施压 | 新人报到 |
| 今日包若仍是旧课生成的 | 假装就是当前课 | 材料可看，但标明过期，点刷新才按新人报到重做 |
| 唤醒包英文小标题 Business Communication | 容易被当成主题 | 只当这课的名字，不当当前主题 |

## 一句话

每位用户只有一本户口本：表 `user_theme_prefs` 里的 `theme`。  
所有「现在练什么」都读它。材料可以暂时是旧课做的，但不能再对外谎称自己是当前主题。

## 谁说了算

- **唯一真源**：`user_theme_prefs.theme`（已有接口 `GET/PUT /api/user/theme`，换主题已有 `POST /api/theme/focus`）。
- **允许改这行的入口**：英语主题选择器（现有）。只写这一行，禁止另开第二本账。
- **成绩单可以有很多主题**：练过 / 通关过仍可留档。那不是「此刻的主题」。

## 实时联动（换主题后自动更新「当前主题」）

点主题选择器之后，**当前主题这四个字必须马上全站变**，不用刷新页面、不用再点别的入口。

复用职业轨迹那套办法（`superme-career-changed`）：

```
选择器改成「危机公关」
        │
        ▼
只写后台一行 user_theme_prefs.theme = 危机公关
        │
        ▼
广播事件 superme-theme-changed { theme: 危机公关 }
        │
        ├── 侧栏立刻变成「当前主题：危机公关」
        ├── 英语 / 精听 / 角色 / 演讲标题立刻变
        └── 每日包区标题立刻变；若材料还是旧课，出过期条
```

规矩：

1. **先写后台，再广播。** 后台没写成功，页面不许装成已经换了（避免两个标签页各说各的）。
2. **所有展示只听这一件事。** 侧栏、英语上下文、唤醒区都听 `superme-theme-changed`，或读同一份内存里的当前主题。谁都不许自己再藏一份「本周主题」。
3. **本地缓存只能跟，不能当主人。** `localStorage.english_theme` 只是跟后台同步的复印件，进页先问后台，复印件和后台打架时以后台为准。
4. **自动更新的是主题字，不是今日材料。** 材料仍按方案 B：标过期，点刷新才重做。不因换主题自动打 AI。

## 谁必须跟着念

这些位置只展示户口本上的中文主题：

- 侧栏（文案从「本周主题」改为「当前主题」）
- 英语首页、进度总控、精听、多角色、演讲
- 每日包接口对外的 `theme` / `currentTheme`
- 凌晨 Cron 的生成入参

禁止再出现：

- 侧栏写死「海外信贷谈判与博弈」
- `GET /api/daily-pack/today` 请求没带主题就默认「商务谈判：让步与施压」
- 用 `wakeup.theme`（如 Business Communication）当「当前主题」
- 浏览器 `localStorage.english_theme` 在后台主题到手之前，拿去当今日包的查找键

## 方案 B：字立刻改，材料标过期

换主题时：

1. 立刻改户口本。
2. 全站标题立刻变成新主题。
3. 不自动重做今日包（避免每次点主题都打 AI）。
4. 若今天已有包，但包是按旧主题生成的：
   - 材料仍可看；
   - 醒目提示：「这份材料还是按『旧主题』生成的，点刷新按『新主题』重做。」
   - 只有用户点刷新（或凌晨 Cron）才按新主题重做。

用现网数据走一遍：

1. 户口本是「新人报到」，全站立刻都写「新人报到」。
2. 今日包还是「商务谈判：让步与施压」做的 → 显示过期条 + 刷新按钮。
3. 点刷新后，包也变成「新人报到」。
4. 侧栏不再出现「海外信贷谈判与博弈」。

## 接口怎么改

`GET/POST /api/daily-pack/today`：

1. 用 `userId` 读户口本，得到 `currentTheme`。没有就按现有 `getOrCreateUserTheme` 建默认主题。
2. **查找今日包不再用请求里的 theme 当身份**。请求里的 theme 忽略，或只作调试，不当查找键。
3. 先找「今天 + 当前主题」的包；没有则取「今天最新一份 ready 包」（现有 fallback 可复用）。
4. 返回至少这些字段：

| 字段 | 含义 |
| --- | --- |
| `currentTheme` | 户口本主题，页面标题只用这个 |
| `theme` | 这份材料实际按哪个主题生成的（包内主题） |
| `stale` | `theme !== currentTheme` 时为 true |
| `status` | 照旧：missing / ready / generating / failed |
| `wakeup` / `flawVocab` | 照旧；`wakeup.theme` 不当当前主题展示 |

刷新接口 `POST /api/daily-pack/regenerate`：主题只取户口本，不取请求里随便传的 theme。

凌晨 Cron：只读户口本，不写死默认商务谈判。

## 页面怎么改

- `Sidebar.tsx`：去掉写死文案；改成「当前主题：{currentTheme}」；听主题变更事件或读同一数据源。
- `EnglishContext`：进页先问后台再定主题；本地缓存只能跟后台，不能反过来覆盖后台。
- 每日唤醒 / 易错词：标题用 `currentTheme`；`stale === true` 时出过期条和现有刷新按钮。
- 进度总控 / 精听 / 多角色 / 演讲：标题用英语上下文里已与后台对齐的主题，不再各读各的。

## 明确不做

- 不改职业画像、声线短板、审美、博弈。
- 不自动因换主题重跑 Dify。
- 不合并「练过的历史主题」和「当前主题」。
- 不把英文小标题提升成主题。

## 验收（用 lzhmy 能对上）

1. 同一时刻：侧栏、英语页、`GET /api/user/theme`、`GET /api/daily-pack/today` 的 `currentTheme` 四个字一样。
2. 若今日包主题不同：`stale=true`，页面有过期提示，材料仍能看。
3. 点刷新后：`stale=false`，包主题等于当前主题。
4. 侧栏只出现「当前主题」，不再出现「本周主题：海外信贷谈判与博弈」。
5. 换主题后不自动生成新包；侧栏和各练习页标题立刻变成新主题（实时联动）。
6. 换主题失败时，全站主题字不变，不出现「侧栏已变、练习页没变」。

## 红队

- 两个标签页各改一个主题：以后写进后台的为准，另一页刷新后跟后台走。
- Cron 正在按旧主题跑、中途改了主题：跑完的包若对不上，标过期，不改户口本。
- 打开页面时本地缓存先闪旧主题：先问后台再画主题字。
