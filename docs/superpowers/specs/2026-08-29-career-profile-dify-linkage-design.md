# 职业路径写入账号画像并驱动 Dify 生成 — 设计说明

**日期：** 2026-08-29  
**状态：** 实现已完成（自动化契约通过；手工验收待用户）。计划见 `docs/superpowers/plans/2026-08-29-career-profile-dify-linkage.md`  
**关联问题：** 侧栏 Career Progression 编辑后与学习内容脱节；需进入登录账号画像，并在全局设置可查看/编辑。

---

## 1. 目标与成功标准

### 1.1 目标

1. 将侧栏「起点职位 / 当前定位 / 意向目标 / 能力匹配度」写入**当前登录账号**画像，而非仅本机展示。
2. 每次调用 Dify 工作流时，把（精炼后的）账号画像作为 `inputs.user_current_profile` 提示，生成针对性学习内容。
3. 在全局设置中提供入口：关闭设置浮层后打开全屏画像页，查看并编辑画像。
4. 进入画像页前用项目已有 LLM（Profile Dedupe）概括精简短板正文，并**自动落库**。
5. **全局最新时效规则：** 所有画像相关内容按最新时效维护；同类主题冲突时只保留最新一条。

### 1.2 非目标（本设计不做）

- 保存职业路径或打开画像后**立刻重跑**当前主题/听力/长文等材料（采用方案 A）。
- 新建独立 Dify 压缩工作流（复用现有 Profile Dedupe）。
- 将职业路径四字段送入 LLM 全文压缩（避免职位名被改写）。
- 新增定时自动精简任务（T1/T2）；时效靠「每次写入按最新合并」+「打开画像时整篇精简」。

### 1.3 成功标准

| # | 标准 |
|---|---|
| S1 | 侧栏「保存并推演」后，当前 `userId` 的服务端/本地画像可读到职业四字段；换机同账号仍在。 |
| S2 | 之后任意经 `injectUserProfile` / 显式传 `user_current_profile` 的 Dify 调用，注入串含职业路径摘要。 |
| S3 | 全局设置「打开画像」→ 关浮层 → LLM 精简并落库 → 打开 P1 页展示落库结果。 |
| S4 | 同类主题先后写入时，后者覆盖前者；注入与页上展示均为最新版。 |
| S5 | 已生成完的旧材料不因画像更新自动重生成（方案 A）。 |

## 2. 已确认决策

| 项 | 结论 |
|---|---|
| 联动策略 | **A**：只写入画像；之后生成自动带新画像 |
| 画像页形态 | **P1**：全屏遮罩页（放大版 ProfileEditModal 风格） |
| 进入精简 | **S1**：进入前 compress，**自动落库**后再展示 |
| 时效 | **全局硬规则**：同类冲突 → 最新时效更新 |
| 额外定时精简 | 不采用 T1/T2，维持写入合并 + 打开整篇精简 |
| Dify 契约 | 沿用起始变量 `user_current_profile`（[执行工作流](https://docs.dify.ai/zh/api-reference/workflow-runs/run-workflow) 的 `inputs`） |

## 3. 现状摘要（问题根因）

| 数据 | 现状 | 问题 |
|---|---|---|
| 职业路径 | `localStorage.superme_career`；侧栏写、顶栏读 | **未**进账号画像，**未**进 Dify 注入 |
| 短板画像正文 | `user_current_profile` + SQLite `user_memories.profile_content` | 已有；周聊/复盘/弹窗可写 |
| 注入 | `injectUserProfile` 拼装短板 + L3 + 错题 + 图谱 + 召回 | **不含** career |
| 全局设置 | 语速、口音、User ID 等 | **无**完整画像查看/编辑入口（短板编辑仅在侧栏 Summary 弹窗） |
| 精简 | `/api/user/profile/compress` → Profile Dedupe | 仅弹窗内手动「精简」；打开设置无此流程 |

### 3.1 当前会写入画像正文的动作

1. `ProfileEditModal` 保存 / 清空 / 精简  
2. 双周复盘 `appendUserProfileFactor`  
3. 周聊（SummaryArea / WeeklyChatModule）`appendUserProfileFactor`  
4. 启动/登录/改 User ID：`loadUserProfileFromServer` 按 `updated_at` 合并  

### 3.2 不写入画像正文（需知情）

- 地区口音偏好 → `super_agent_accent_pref` / L3  
- 口语战房会话弱点 → 会话内存 / weakness log  
- 职业路径「保存并推演」→ **仅** `superme_career`（本设计要改）

## 4. 架构与数据流

```
侧栏 Career 保存                    全局设置 [打开画像]
       │                                    │
       ▼                                    ├─ 关闭设置浮层
 写账号职业路径（结构化）                      │
 本地 + 服务端（与 userId 绑定）               ├─ Loading：compress 短板正文
       │                                    │     自动落库 + updated_at
       │                                    ▼
       │                              P1 全屏画像页
       │                              · 职业四字段（可编辑）
       │                              · 短板正文（已精简，可再改）
       │                              · 注入预览（只读）
       │                                    │
       └──────────► 保存画像 ◄───────────────┘
                         │
                         ▼
              账号真相：career + profile_content
                         │
         之后任意 Dify 调用（方案 A）
                         │
                         ▼
         inject：现读 career 摘要 + 精炼短板 (+ L3/错题/图谱等)
                         │
                         ▼
         inputs.user_current_profile → 生成针对性内容
```

### 4.1 全局最新时效规则（硬约束）

适用于**所有**画像相关写入：

1. 按语义主题对齐已有条目（口音/目标/具体短板/职业阶段相关描述等）。  
2. **同类主题冲突 → 只保留时效更新的一条**（增量合并与整篇精简均如此）。  
3. 不同主题全部保留；更新 `updated_at`。  
4. 职业路径为**结构化字段覆盖**：每次保存以本次值为该字段最新真相，不经 LLM 改写职位字符串。  
5. 启动/换账号：本地与服务端按 `updated_at` 取新，禁止旧端覆盖新端。  
6. Dify 注入**现读**落库结果，不使用过期缓存串作为画像正文来源。

实现上优先复用现有 `mergeProfileWithDedupe` / `compressProfileContent` / Profile Dedupe 工作流提示词中的「同类保留最新」规则；若某写入路径仍是朴素 `append` 而未走 dedupe，实现阶段应改为走合并（保证规则落地）。

### 4.2 注入串形态（示例）

```
职业路径: 起点=高级经理 (Senior Manager); 当前=总监 (Director); 目标=合伙人 (Partner / Managing Director); 能力匹配度=23%; <精炼短板正文>; [既有 L3/错题/图谱/召回若有]
```

长度：沿用现有 sanitize 与各通道截断策略；职业摘要宜短，优先保证四字段可读。

### 4.3 Dify 对齐说明

- 官方路径：Workflow 通过 `POST /workflows/run` 的 `inputs` 传入起始变量。  
- 本仓库大量 yml 已声明 `user_current_profile`；本设计**不改**变量名，只保证注入内容含职业路径 + 精炼短板。  
- 不要求为职业路径新增四个独立 Dify 变量（最小改动）；若未来要结构化变量，另开设计。

## 5. UI 设计

### 5.1 全局设置入口

在「全局统筹」面板中新增区块「当前账号画像」：

- 一行预览：职业短名（当前→目标）· 匹配度 · 短板截断。  
- 主按钮「打开」：  
  1. 关闭全局设置浮层；  
  2. 进入压缩 Loading；  
  3. 打开 P1 画像页。

### 5.2 进入 Loading

- 文案：「正在概括并精简画像…」  
- 调用现有 `compressUserProfile(..., save=true)`（S1 自动落库）。  
- 可「取消」：中断则不打开画像页；若请求已成功落库，取消不回滚（可接受；实现时可文档化）。  
- 空画像：跳过 LLM，直接打开页（职业仍可编辑）。  
- 失败：提示错误；可选「仍打开未精简版本」——实现时默认**提示失败并允许打开当前落库内容**，避免卡死。

### 5.3 P1 全屏画像页

| 区域 | 内容 | 行为 |
|---|---|---|
| 顶栏 | 返回、账号 id、精简角标（如 120→48 字） | 返回关闭页，不自动重开全局设置 |
| 左 | 职业路径四字段 | 与侧栏同源；可编辑 |
| 右 | 短板全文 | 展示 S1 落库结果；可再编辑；「再次精简」「清空」 |
| 中/下 | 注入预览 | 只读；拼接职业 + 短板（及说明） |
| 底 | 取消 / 保存画像 | 保存：职业 + 短板一并写入账号并广播 |

与现有 `ProfileEditModal` 关系：P1 为全局设置主入口的放大页；侧栏短板弹窗可保留或后续改为打开同一 P1（实现阶段优先**最小改动**：先加 P1，侧栏弹窗暂可并存，避免大范围替换，除非评审要求统一）。

## 6. 数据与持久化

### 6.1 职业路径

- **现状键：** `superme_career`（本机）。  
- **目标：** 绑定 `getAppUserId()`，与画像同账号可读。  
- **推荐落点（实现择一，优先成熟最小改动）：**  
  - **R1（推荐）：** 写入 `user_memories.memory_layers` 下结构化字段（如 `l3_vars` 旁或 `career_path` 对象），随现有 profile GET/SAVE/ingest 同步；本地仍可镜像一份便于侧栏秒开。  
  - **R2：** 仅扩展 `profile/save` body 增加 `careerPath` 列或 JSON 字段。  

设计约束：换 User ID 必须加载该账号 career；默认值可与现有 `DEFAULT_CAREER_PATH` 一致。

### 6.2 短板正文

- 继续使用 `profile_content` / `user_current_profile`。  
- S1 与「再次精简」走 `/api/user/profile/compress`。  
- 增量写入统一走「最新时效」合并（见 §4.1）。

### 6.3 事件

- 已有：`superme-career-changed`、`global-profile-changed`。  
- 保存职业或短板后应派发相应事件，顶栏 Evolution、注入刷新、侧栏展示保持一致。

## 8. 错误处理与边界

| 场景 | 行为 |
|---|---|
| compress 失败 | 提示；允许打开当前未精简内容；不阻断查看职业 |
| 短板为空 | 不调 compress；页上可编辑职业 |
| 用户打开后不点保存 | S1 已落库精简短板；职业若仅在页上改而未保存则不落库 |
| 侧栏保存职业 | 立即落库职业；不强制立刻 compress 短板 |
| 方案 A | 不触发材料重生成 |

## 9. 测试计划（验收）

### 功能 1：职业路径入账号并注入

- **路径：** 侧栏 Career → 编辑 → 保存并推演 → 触发任一会传 `user_current_profile` 的生成（或单测 inject）。  
- **数据：** 目标改为「合伙人」、匹配度 23%。  
- **预期：** 账号存储含该四字段；inject 结果含「能力匹配度=23%」与目标文案。  
- **对应需求：** §1.1-1、§1.1-2。

### 功能 2：全局设置打开画像 S1

- **路径：** 全局设置 → 打开画像。  
- **预期：** 设置关闭 → Loading → 短板变短并已落库 → P1 展示与预览一致。  
- **对应需求：** §1.1-3、§1.1-4。

### 功能 3：同类主题最新时效

- **路径：** 先写入主题 A 旧描述，再写入主题 A 新描述（或两次 compress/merge）。  
- **预期：** 画像中仅保留新描述。  
- **对应需求：** §1.1-5。

### 功能 4：账号隔离

- **路径：** 用户 A 设职业 → 切换 User ID 到 B → 再切回 A。  
- **预期：** A/B career 与短板不串；切回 A 仍见 A 的最新值。

## 10. 风险与假设

| 风险/假设 | 说明 |
|---|---|
| 假设 | `DIFY_PROFILE_DEDUPE_API_KEY` 在目标环境可用；否则本地 dedupe 兜底，语义时效弱于 LLM |
| 风险 | 注入串变长触发既有截断（如 embed 120/280 字）→ 实现时职业摘要优先放前，避免被截掉 |
| 风险 | 侧栏 ProfileEditModal 与 P1 双入口短期并存可能造成两套 UI → 可后续收敛 |
| 假设 | 用户接受方案 A：旧材料不自动刷新 |
