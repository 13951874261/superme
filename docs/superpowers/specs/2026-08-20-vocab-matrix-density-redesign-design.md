# 词汇矩阵页面高密度重设计

**日期：** 2026-08-20  
**状态：** Spec 已确认；实施计划见 `docs/superpowers/plans/2026-08-20-vocab-matrix-density-redesign.md`  
**范围：** 英语模块 → 词汇矩阵（`VocabTab` 翻转后 `Target Revealed` 态）

## 1. 问题与目标

### 问题

当前翻转后布局为「左栏词典视图（约 7 列）+ 右栏三块辅助卡（约 5 列）」。当词典内容较短时，左栏下方会出现大面积空白；用户感知为「页面过于空旷」，学习信息未能填满主舞台。

### 目标

在**学习密度优先**前提下，采用已确认方案 A：

- 左上：词条主卡（学习化、高密度）
- 左下：保留圆形主视觉，改造为「圆形记忆矩阵」主舞台
- 右侧：保留三块结构，压缩留白并工具化

成功标准：

1. 首屏不再出现大面积装饰性空白
2. 左下圆区承载真实学习内容，而非空边框
3. 右侧三卡保留，信息更紧凑、可行动
4. 用户路径清晰：`看词 → 建联想 → 看反馈 → 看场景`
5. 动效轻量、不抢内容、不卡顿

## 2. 已确认决策

| 项 | 决策 |
| --- | --- |
| 设计取向 | 学习密度优先（非视觉海报优先） |
| 圆形主视觉 | 保留，改造为记忆矩阵主舞台 |
| 右侧结构 | 保留三块：记忆生成 / SM-2 仪表盘 / 商务 SOP |
| 方案 | 方案 A：主卡 + 圆形记忆矩阵 + 右侧压缩辅助栏 |
| 圆区结构 | 圆心 + 第一环 + 第二环 + 下沿辅助条 |
| 动效 | 轻量 GSAP；仅 `transform` / `opacity` |

## 4. 布局设计

### 4.1 骨架（桌面 `lg+`）

```text
┌─────────────────────────────┬──────────────────────┐
│ 左上：词条主卡 (col ~7)      │ 右上：记忆生成工具卡  │
│ 释义 / 同义词 / 搭配 / 例句  │ tabs + prompt + 生成 │
├─────────────────────────────┼──────────────────────┤
│ 左下：圆形记忆矩阵           │ 右中：SM-2 仪表盘    │
│ 圆心 + 双环 + 下沿辅助条     │ 留存率 + 三要素 + 排期│
│                             ├──────────────────────┤
│                             │ 右下：商务场景 SOP    │
│                             │ 1 场景 + 1 表达 + 提示│
└─────────────────────────────┴──────────────────────┘
```

移动端：单列堆叠，顺序为 `主卡 → 记忆矩阵 → 右上 → 右中 → 右下`。

### 4.2 左上主卡（学习化）

在现有词典视图基础上提高同屏信息密度：

- 头部：词条、音标、发音、必要标签
- 核心义：中文释义优先可见
- 快速学习区：同义词、搭配、一条最强场景/例句尽量同屏
- 低频信息可保留折叠，但不把「同义词/搭配」默认埋藏

示例（词条 `strategic flexibility`）：

- 释义：战略灵活性；根据环境变化调整方向与行动方案
- 同义词：adaptability / agility / versatility
- 搭配：maintain strategic flexibility / enhance operational flexibility
- 例句：一条带发音的最强句

### 4.3 左下圆形记忆矩阵

#### 圆心层（固定）

- 主词/短语
- 中文核心义（短）
- 可选一枚最短记忆标签（如「应变」）

#### 第一环（4–6 节点）

来源优先级：`synonyms` → `collocations` → `scenarios` 标签。  
不足则用现有 payload 中可用字段补齐；仍不足则减少节点数，不强行占位假数据。

#### 第二环（3–5 节点）

- 图片记忆入口（有 `image_url` 则缩略图，否则入口态）
- 联想句 / 助记短语摘要
- 词根词缀摘要
- 可选商务情境钩子

#### 下沿辅助条

- 一句记忆钩子文案
- 操作：查看大图 / 切换记忆模式 / 发音  
  （操作与说明移出圆内，避免圆心拥挤）

节点分布：用 `gsap.utils`（如角度映射、`clamp`、轻微扰动）计算位置，避免大量硬编码坐标。

### 4.4 右侧三卡（工具化压缩）

**右上 · 生词记忆辅助**

- 保留 tabs（词根 / 联想 / 助记 / 图片）
- 压缩大段空白 prompt 展示区：默认摘要 + 可展开全文
- 主 CTA：生成/刷新记忆图片
- 次级状态：上次生成时间或「可重生」提示

**右中 · SM-2 仪表盘**

- 保留留存率条、复习轮次、衰退间隔、难易因子、下次排期
- 增加一句行动提示（例：「今日仍需高质量回忆」），从「展示数据」转为「指导下一步」
- 压缩内边距与装饰空白

**右下 · 高管商务 SOP**

- 只突出 1 个当前相关场景
- 1 条推荐表达
- 1 条使用提示
- 可选「换一个场景」；不做长篇说明书

## 5. 动效规范

技术栈为 React，已依赖 `gsap` 与 `@gsap/react`。实现时以 **React 生命周期规范**（`useGSAP` / `gsap.context` + cleanup）为准；同时遵守用户指定的性能与 utils 约束。

### 允许

- 切词时：主卡内容短促 `opacity` + 轻微 `y` 淡入
- 圆区：节点按序 stagger 浮现（`opacity` + `scale`）
- 右侧三卡：极短同步淡入
- hover：节点轻微 `scale`（可选）

### 禁止

- 持续旋转、持续 pulse 抢注意力
- 动画 `top` / `left` / `width` / `height` 引发布局抖动
- 整页大幅飞入
- 无 cleanup 的全局选择器动画

### 无障碍

- 尊重 `prefers-reduced-motion`：降级为瞬时或仅 opacity 交叉淡入
- 内容默认可见，不依赖「动画跑完才显示」

## 6. 数据流

不新增后端协议。矩阵节点从现有字段组装：

```text
currentWord.payload
  → synonyms / antonyms / collocations / scenarios / meaning*
MemoryAidPanel / getMemoryAids(wordId)
  → root_memory / association_memory / mnemonic_phrase / image_url / image_prompt
SM-2 字段
  → repetitions / interval_days / ease_factor / next_review_date
```

缺字段时：

- 圆区减少节点，不渲染空壳假标签
- 图片节点显示「待生成」入口，点击可聚焦右上生成卡或触发既有生成流程

## 9. 风险与假设

- **假设：** 用户截图中的大块空白主要来自左栏短内容后的纵向空洞；用记忆矩阵填补该空洞即可满足「不要过于空旷」。
- **风险：** 圆区节点过多会乱。对策：硬性上限（一环 ≤6，二环 ≤5）并用 utils 均匀分布。
- **风险：** 同时改 DictionaryPanel 可能影响独立词典面板。对策：优先在 VocabTab 层包装布局；仅在确需时做 DictionaryPanel 的局部、可开关样式调整。

## 10. 范围声明（YAGNI）

不做：

- 3D / 粒子 / 持续轨道动画
- 重写词典数据结构或 Dify 协议
- 合并右侧三卡为一块超级面板
- 改 FlashCard 弹窗 UI（除非后续单独需求）
