# 登录登记与每日内容补跑设计

## 目标

保证页面成功登录的用户会可靠写入 `user_login_logs` 与 `user_theme_prefs`；若用户错过 02:00 任务且当天内容不存在，则在不阻塞登录响应的前提下补生成唤醒、破绽、长文和音频。

## 数据流

1. 前端完成账号规范化后，先调用 `POST /api/user/login-ping`，检查 HTTP 与业务响应；失败时记录明确日志，但不阻止用户进入系统。
2. 后端同步落库登录时间与主题后立即返回成功。
3. 后端按 `userId + packDate` 去重启动后台 catch-up：
   - 当日唤醒/破绽包不存在时调用现有 `generateDailyPackForUser`。
   - 复用现有精听组合生成器，只为当前用户补齐缺失长文与音频。
4. 同一进程中同一用户同一天只允许一个 catch-up Promise，避免 LoginPage 与 App 双打点造成重复生成。

## 诊断

新增只读脚本，输出指定用户的主题、近 7 天登录、当天包、长文和音频统计。服务器执行示例：

```bash
cd /var/www/super-agent/vocab-server
node scripts/check-user-daily-readiness.js lzhmy
```

## 错误处理

- 登录登记落库失败：接口返回 500，前端输出包含用户 ID 的错误日志。
- 后台补跑失败：写服务日志，不回滚已成功的登录记录，也不影响登录响应。
- 单个长文/音频组合失败：继续处理其余组合并汇总错误。

## 验收

- 登录 `lzhmy` 后，主题与登录表均能查询到该用户。
- 当天无包时，登录接口快速返回，并在后台启动一次补跑。
- 重复打点不会并发启动重复补跑。
- 诊断脚本能区分“用户未登记”“包缺失”“长文/音频缺失”。
- 现有 02:00 cron 行为保持不变。
