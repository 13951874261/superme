# 词库内容恢复与紧凑展示设计

## 目标

修复“统计有词条、列表和词汇矩阵为空”的分类语义错位，并在约 6,000 条词、约 5,900 条待复习数据量下保持分页、复习队列和界面数字一致。

## 已确认的产品决策

- 历史上 `category` 不是 `business` 或 `general` 的词条，统一归入 `business`。
- 既有 `general` 词条保持不变。
- 未来批量提取的词条固定写入 `category='business'`；提取主题仅保存在 `payload`。
- 词汇矩阵继续采用“单词学习卡 + 队列进度”，不改为全量词卡网格。
- 请求失败且有本地缓存时，自动重试一次；仍失败则继续展示缓存并提示同步状态。
- 请求失败且没有缓存时，显示可重试错误态，不显示“今日词汇已清空”。

## 根因

批量入库路径将 `topic` 写入了 `vocabulary.category`，例如 `finance`、`daily_extraction`；前端仅把 `business` 和 `general` 视为有效分区。统计接口不做分区过滤，因此能显示总数；列表和词汇矩阵在客户端过滤后为空。

分页改造后，这个问题还导致了空列表与“加载更多”同时出现：`hasMore` 由服务端全库分页计算，而页面在该页数据返回后才过滤掉错误分类。

## 数据与接口设计

### 历史数据归一化

应用启动迁移中执行一次幂等更新：

```sql
UPDATE vocabulary
SET category = 'business'
WHERE category IS NULL OR category NOT IN ('business', 'general');
```

该迁移不触碰已归类为 `general` 的词条，也不修改词条正文、复习历史或 SM-2 字段。

### 新增词条

批量素材提取、每日提取和句型提取路径统一写入：

```text
category: business
payload.topic: 原始主题
```

不再把主题名写入 `category`。手动新增路径保留其现有业务语义，不在本次范围内扩展分区选择功能。

### 分区分页

`/api/vocab/list` 和 `/api/vocab/review` 支持：

```text
category=business|general
limit=1..100
offset>=0
```

服务端按以下顺序处理：分区过滤、复习条件过滤（仅 review）、排序、`LIMIT/OFFSET`，最后基于同一结果集返回 `items` 与 `hasMore`。因此，空分区不会再返回误导性的 `hasMore=true`。

`review` 也支持 `offset`，使复习组件完成第一批 50 个词后能请求下一批，而非重复首批。

### 统计

`/stats` 保持统计总量与到期数。前端不再用当前加载的 50 条 review 数据覆盖 `dueToday`，避免“5939 / 50”来回跳变。

## 前端设计

### 艾宾浩斯生词本

- 请求当前分区的 `/list` 结果，不再在已分页数据上执行分区过滤。
- 词条列表使用既有虚拟滚动与“加载更多”交互。
- 仅当当前分区还有后续词条时显示“加载更多”。
- “复习 N”按当前分区的同源 review 队列显示。

### 词汇矩阵

- 请求当前分区的 `/review?limit=50&offset=N`。
- 维持单词学习卡、造句评估、翻转及既有 SM-2 流程。
- 显示当前批次与全队列进度，例如“第 1 / 5939 个”。
- 完成一批 50 个词时自动请求下一批；请求结果追加到学习队列或替换已完成批次，确保不重复。

### 缓存和失败态

1. 有缓存时立即呈现缓存中的学习卡并发起后台同步。
2. 网络请求失败时自动重试一次。
3. 两次失败后继续显示缓存，展示“正在使用上次同步内容”的非阻塞提示。
4. 无缓存时展示“连接失败”与“重新加载”入口。
5. 只有服务端成功返回空队列时才显示“今日词汇已清空”。

## 非目标

- 不改变 SM-2 算法、复习历史、造句评分和翻转逻辑。
- 不制作全量词汇矩阵网格。
- 不新增依赖或重构既有视觉系统。
- 不修改 CSV 导出语义。

## 验收标准

1. 历史词条在“政商务区”可见，统计与列表不再产生“有数但空白”。
2. 两个页面的复习数量与当前分区队列一致。
3. 分区无数据时不显示“加载更多”。
4. 连续完成两批 50 个待复习词，第二批不与第一批重复。
5. 有缓存且断网时，学习卡仍可操作；无缓存断网时提供重试入口。
6. 造句、翻转、导出和手动收录的现有回归行为保持可用。
